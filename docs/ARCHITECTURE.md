# Architecture

## The big picture

```
 Browser ──► Vercel (static files from this repo, deployed on push)
   │            ├─ /            homepage (hand-edited index.html)
   │            ├─ /shop        shop app (generated from _source/site2/index.html)
   │            ├─ /shop/<slug> pre-rendered product + collection pages (generated, for SEO)
   │            ├─ /account     member area (generated from _source/account/template.html)
   │            └─ /api/*       Vercel serverless functions (Node)
   │
   ├──► Shopify Storefront API (public token, from the browser)
   │       live prices, variants, stock; builds the cart and opens Shopify's hosted checkout
   ├──► Supabase (public key, from the browser): sign-in, profiles, saved items, behaviour events
   ├──► Klaviyo client API (public key T9JJzp): sign-ups, events, reviews widgets
   └──► GA4 / Meta pixel / Clarity: analytics (IDs in assets/pmn-config.js)

 Shopify checkout ──► order ──► Fulfill Engine ──► JQF Printing prints + ships
 /api/account/*  ──► Shopify Admin API + Supabase (server keys in Vercel env)
 /api/reels      ──► Instagram Graph API (IG_ACCESS_TOKEN)
```

There is **no framework and no bundler**. Pages are plain HTML with inline CSS/JS. Python scripts in `_source/`
generate the shop. Generated output is **committed**: Vercel just serves the repo (it ignores `_source/`, see
`.vercelignore`).

## How a product is defined (3 places + Shopify)

1. **`_source/site2/index.html`**
   - `META["<id>"]`: spin frame size, sprite layout, `hi` = map of angle → 2K still name, `seo` slug. Printed by `add_spin.py`.
   - `PRODUCTS[]`: `{id, name, short, price, kind:"tee"|"hat", team:"samoa"|"tonga"|"pmn", swatch, colourName, world/glow/flood/wordc (background colours), opts:[colour swatches / related]}`.
     **Order of this array = order of the hero carousel.**
   - `COPY["<id>"]`: one-line pitch + 3 bullet points for the product page.
   - `REST["<id>"]`: angle the product page opens on (e.g. 180 = back print). Missing = front.
   - Sizes come from `BLANK` via `blankFor(p)`: black standard tees `fwjCore` (S–5XL), red/royal `fwjColour` (L–3XL),
     oversized (S–5XL), hats (one size). Colour tees show the full S–5XL ladder with unavailable sizes crossed out.
2. **`_source/seo_content.py`** `P["<id>"]`: meta description, keyword, description paragraphs, product FAQ.
3. **`_source/shopify_layer.js`** `SHOPIFY_MAP["<id>"] = ["<shopify-handle>", "<Color option value>"]`.
4. Optional: `_source/seo_build.py` `GROUP` (links colourways as one ProductGroup for Google),
   `_source/account/template.html` (`SITE_ID` title regex, `HANDLE`, `KL_PID` Shopify product ids for reviews/Buy again).
5. **Shopify**: product active, **published to "Polynesian Music Network Headless"**, variants `Color / Size`, and added
   to the **Buy 3 tees, get 1 free** discount.

Product ids follow `<team>-<design>-<colour>`: `toa-` = Toa Samoa, `mmt-` = Mate Ma'a Tonga, `pmn-` = PMN+ core.
The colour-swap logic in the account page relies on black ids ending in `-black` and colour ids ending in `-red` / `-royal`.

## Runtime behaviour worth knowing

- **Shopify wins on price.** On load, `shopify_layer.js` fetches up to 250 products and overwrites `PRODUCTS[].price`
  with the Shopify price. If Shopify doesn't return a product (not published to Headless, wrong handle, wrong Color
  value), its variants are missing and checkout refuses that line.
- **The bag** lives in `localStorage.pmn_cart` (`[{id,size,qty}]`). On load, sizes a colour isn't sold in are cleared.
  Checkout builds a fresh Shopify cart each time (`pmn_scart` holds the last cart id).
- **Buy 3 get 1** is a Shopify **automatic** discount; the site only *predicts* it to show savings in the bag
  (`bx()` in `site2/index.html`). Both must agree; see `BUSINESS-RULES.md`.
- **Deep links:** `/shop?hero=<id>` centres a product in the hero; `/shop#toa-samoa` etc. open a collection;
  `/shop/?review=<shopify id>` opens the review form.
- **Accounts:** Supabase Auth (6-digit email code via Resend SMTP, Google sign-in). `/api/account/link` finds or creates
  the Shopify customer by email and tags them `pmn-member` (which unlocks `MEMBER10`). `/api/account/orders` returns
  their orders. Tables + row-level security: `_source/account/schema.sql`.
- **Tracking:** behaviour events go to Supabase `events` with an anonymous id `pmn_aid`, claimed on sign-in.
